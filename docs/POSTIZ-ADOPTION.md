# اعتماد ودمج مصدر Postiz

## المصدر المثبّت

- مستودع المصدر: https://github.com/mghalaosimi-web/mghal-digital-automation
- المسار في هذا المستودع: `integrations/postiz` (Git submodule).
- Commit المثبّت: `e94383568f7549c373a985f4521021c4353e1a37`.
- الترخيص: GNU AGPL-3.0؛ تم الاحتفاظ بملف LICENSE وإشعارات المصدر داخل المستودع الفرعي.
- البنية: pnpm monorepo يضم Next.js frontend وNestJS backend وPrisma/PostgreSQL وTemporal وbrowser extension.

## طريقة الحصول على المصدر

```bash
git clone --recurse-submodules https://github.com/mghalaosimi-web/mghal-digital-os.git
```

أو بعد استنساخ المستودع الرئيسي:

```bash
git submodule update --init --recursive
```

التثبيت الحالي يحفظ مصدر Postiz كاملاً كمكوّن Git مستقل مثبت على commit معروف؛ لا ينسخ جميع ملفاته إلى جذر تطبيق MGHAL ولا يخلط اعتمادياته أو قاعدة بياناته مع التطبيق الحالي.

## حدود التشغيل والدمج

MGHAL Digital OS هو التطبيق المركزي المنشور حالياً. Postiz تطبيق مستقل متعدد الخدمات وليس مكتبة Next.js قابلة للاستيراد مباشرة. يتطلب Node.js 22.12+ وpnpm workspaces وخدمات frontend/backend وTemporal وقاعدة PostgreSQL وإعدادات OAuth/التخزين الخاصة به.

لذلك:
- لا تغيّر أمر البناء الجذري في Render إلى أوامر Postiz.
- لا تشغّل `prisma-db-push` أو `prisma-reset` من Postiz على قاعدة MGHAL الإنتاجية.
- لا تنسخ متغيرات البيئة أو أسرار OAuth بين الخدمتين.
- لا تفعّل النشر الاجتماعي قبل ربط تطبيقات OAuth الرسمية والتحقق من صلاحيات كل منصة.
- يمكن لاحقاً فصل تشغيل Postiz كخدمة مستقلة وربطها بواجهات API موثقة بعد إعداد بيئة تشغيل مناسبة، دون إيقاف النظام المركزي.

## الترخيص والامتثال

Postiz مرخّص تحت AGPL-3.0. يجب إبقاء إشعارات حقوق النشر وملف الترخيص للمصدر كما هي. عند تعديل نسخة Postiz وتشغيلها كخدمة عبر الشبكة، تنطبق متطلبات AGPL-3.0 المتعلقة بإتاحة Corresponding Source لمستخدمي النسخة المعدلة عبر الشبكة. هذا المستودع يحتفظ بمصدر Postiz كمكوّن مستقل عبر submodule؛ لا تُزل حدود المكوّن أو إشعاراته ولا تقدّم مصدره على أنه ملكية حصرية جديدة.

هذه ملاحظات هندسية وليست استشارة قانونية.

## ما سيُدمج تدريجياً في واجهة MGHAL

- إدارة القنوات الاجتماعية وربط الحسابات عبر OAuth الرسمي.
- محرر منشورات مع صيغ منفصلة لكل منصة.
- تقويم موحد للمنشورات وجدولة القنوات.
- حالات المراجعة والاعتماد والنشر والفشل.
- سجل نشر وإعادة محاولة آمنة مع idempotency.
- تحليلات المنصات حيث تسمح APIs الرسمية.

وجود المصدر داخل submodule لا يعني أن هذه الوظائف أصبحت مفعلة داخل تطبيق MGHAL أو أن مفاتيح OAuth قد تم إعدادها.
