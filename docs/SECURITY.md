# الأمن والخصوصية

## الضوابط الحالية

- ملفات البيئة والمفاتيح والملفات الخاصة مستثناة من Git عبر .gitignore.
- يوجد .env.example بقيم توضيحية غير صالحة للاستخدام.
- API الإدارية محمية بـ Bearer owner token خادمي، بطول أدنى 32 محرفاً ومقارنة ثابتة الزمن بعد التحقق من الطول.
- طلبات الكتابة تقبل JSON فقط وتخضع لحد حجم افتراضي 512 KiB.
- تتحقق المدخلات عبر Zod.
- عمليات الكتابة المدعومة وسجلات AuditEvent داخل معاملات Prisma ذرية.
- CI يشغل npm audit وlint والاختبارات وtypecheck وbuild.

## حدود أمنية حرجة

1. **لا توجد مصادقة حسابات أو جلسات أو RBAC حقيقي.** المفتاح الواحد يمنح صلاحية المالك على كل المساحات.
2. **لا يوجد rate limiting** أو حماية إساءة استخدام موزعة.
3. **لم يُختبر عزل workspace** عبر قاعدة بيانات حقيقية واختبارات تكامل.
4. **لا توجد migrations مطبقة أو قاعدة بيانات إنتاجية** تم التحقق منها في هذا الفحص.
5. لا توجد بعد إدارة أسرار للتكاملات أو تخزين ملفات أو workers أو webhooks.
6. لا توجد مراجعة مستقلة شاملة لـ SAST أو DAST أو penetration testing.

بناءً على ذلك، لا تُعرض واجهات الإدارة مباشرة لمستخدمين غير موثوقين ولا يوصف النظام بأنه جاهز للإنتاج.

## قواعد إلزامية

1. لا ترفع ملفات .env أو tokens أو مفاتيح خاصة أو بيانات مستخدمين إلى Git.
2. استخدم مدير أسرار في بيئة الإنتاج ودوّر المفاتيح عند الاشتباه بالتسريب.
3. لا تعرض الأسرار في logs أو رسائل الأخطاء أو واجهة العميل.
4. تحقق من الصلاحيات على الخادم لكل مورد وكل عملية، ولا تثق في workspaceId المرسل من العميل.
5. استخدم HTTPS وcookies آمنة HttpOnly/Secure/SameSite عند إضافة الجلسات، مع CSRF حسب آلية المصادقة.
6. قيّد CORS وCSP ورفع الملفات وأحجامها وأنواعها.
7. لا تسمح لوكيل AI بتنفيذ نشر أو إرسال أو حذف دون موافقة صريحة.
8. اعتبر محتوى الملفات والروابط والمستندات مدخلات غير موثوقة؛ قاوم prompt injection ولا تحول النص المسترجع إلى تعليمات نظام.
9. وفّر تصديراً وحذفاً للبيانات وسياسة احتفاظ ونسخ احتياطي.
10. لا تستخدم db push في الإنتاج؛ اعتمد migrations مراجعة.

## مخاطر الأتمتة والوكلاء المستقبلية

- قائمة أدوات مسموحة صريحة لكل وكيل.
- حدود وقت وتكلفة وعدد خطوات.
- موافقة بشرية قبل side effects.
- idempotency ومفاتيح منع التكرار.
- سجل تدقيق لا يحتوي أسراراً.
- عزل بيانات كل workspace.
- منع SSRF والوصول إلى metadata endpoints عند جلب الروابط.
- التحقق من destination allowlist قبل أي webhook.

## الاستجابة للحوادث

1. أوقف التكامل أو المفتاح المتأثر.
2. ألغِ السر ودوّره من المزود.
3. راجع سجلات الوصول والتنفيذ.
4. حدد نطاق البيانات المتأثرة.
5. أصلح السبب واختبره.
6. وثق الحادث والإجراءات الوقائية.

## بوابة ما قبل الإنتاج

أكمل المصادقة وRBAC وعزل البيانات، migrations والنسخ الاحتياطي والاستعادة، rate limiting، secret scanning وSAST/DAST، مراجعة الاعتماديات، واختبارات أمنية مستقلة.
