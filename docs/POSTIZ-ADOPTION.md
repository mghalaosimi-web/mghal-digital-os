# اعتماد Postiz كمكوّن لإدارة الشبكات الاجتماعية

- الإصدار المرجعي المثبّت عند الدراسة: `bd8353f09f8dbaec54f15985f26d34b56ac69636`

- التقنية المعلنة: pnpm monorepo، Next.js، NestJS، Prisma/PostgreSQL، Temporal، وResend.

## قرار الدمج

Postiz ليس مكتبة React يمكن نسخ مجلد منها داخل تطبيق Next.js الحالي. إنه تطبيق متكامل متعدد الخدمات وله دورة نشر وتشغيل واعتماديات مستقلة. لذلك يكون الدمج الآمن على مرحلتين:

1. إبقاء MGHAL Digital OS هو النظام المركزي للهوية والمشاريع والمعرفة والمحتوى وسير الموافقات.
2. تشغيل Postiz كخدمة مستقلة عند توفر بيئة تشغيل مناسبة، ثم ربطه عبر API أو واجهات تكامل موثقة؛ لا نخلط قواعد البيانات أو جلسات الدخول أو أسرار OAuth بين النظامين.

لا تُنسخ شيفرة Postiz إلى هذا المستودع في هذه المرحلة. السبب أن AGPL-3.0 ترخيص copyleft له التزامات عند توزيع عمل مشتق أو تشغيل نسخة معدلة عبر الشبكة. قبل أي دمج شيفري مباشر يجب مراجعة التزامات الترخيص، وإظهار الإشعارات المناسبة، وتوفير مصدر النسخة المعدلة للمستخدمين المتفاعلين عبر الشبكة وفق شروط الترخيص. هذه ملاحظة هندسية وليست استشارة قانونية.

## ما نستفيد منه داخل MGHAL

- منشور رئيسي واحد مع صياغة مستقلة لكل منصة.
- حالات منفصلة للمراجعة والاعتماد والجدولة والنشر والفشل.
- تقويم موحد ومتابعة حالة كل قناة.
- طبقة موحدة لمزودي المنصات، مع OAuth رسمي وعدم استخدام scraping.
- نشر لا يحدث إلا بعد موافقة صريحة.
- سجلات نتائج وإعادة محاولة آمنة عبر idempotency.

## القيود التي يجب عدم إخفائها

- وجود نسخة قناة بحالة SCHEDULED لا يعني أنها نُشرت أو أن هناك worker ينفذها.
- لا توجد حسابات اجتماعية متصلة أو مفاتيح تطبيقات OAuth مثبتة حالياً.
- اعتماد كل منصة يحتاج تطبيق مطور وموافقة ونطاقات OAuth وسياسات نشر خاصة بها.
- لا نشغل Postiz أو Temporal أو خدمات إضافية على Render Free قبل فحص استهلاك الموارد والتكلفة؛ لا يتم إنشاء أي مورد مدفوع تلقائياً.
